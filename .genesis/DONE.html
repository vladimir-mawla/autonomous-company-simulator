1 · The Locked Spec (what we are building)

Cognitive job: Given an append-only log of grants, revocations and commitments, decide for every commitment whether it binds the organisation, and who answers for it — against the record as it stood when the act was made. See .genesis/PLAN.md §2–§5 for the full claim and the closed vocabulary.

Inputs: typed events (grant · revoke · commit)  →  Outputs: a closed Standing (binding · inherited · void), always with its Warrant or its Breach, or a typed Rejection / FoldFault; never a boolean, never a score.

Autonomy level: Fully autonomous end to end — admission, verdict and standing involve no human; humans appear only as roots of authority (the charter).

Failure tolerance: Fail toward the weaker standing — an unprovable act is void, an unreadable log is a FoldFault; a revocation never voids a validly-made commitment and never returns spent authority.

Filled during Genesis (G0–G2, .genesis/PLAN.md, §16 handoff to G3), following the shape used in the sibling projects' own .genesis/DONE.html — content is project-specific, structure only is borrowed. No engine code exists yet: M1 (contracts) is a separate milestone with its own PR and its own verifier.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

Dependency direction inward, zero cycles: lib/contracts → lib/chain → lib/allowance → lib/standing → domains/company, one-directional (modular-architecture gate)
npm run typecheck clean AND npm test green
One verify pass by a separate agent/model (L4) per milestone
No earlier milestone's freeze boundary touched by a later milestone (freeze-boundary gate — the independent verifier's first job on every milestone)
A void Standing carrying a warrant (or an inherited Standing without a heir) does not compile (disjoint-variants gate, from M1)
Conservation holds at every prefix of every generated log (conservation gate, from M4/M5)
A commit's verdict never depends on a later event (prefix-determinism gate, from M5)
void is absorbing: no later event turns a void standing into anything else (lattice gate, from M5)
The live demo and npm run demo:company produce the same standings, diffed by the verifier (deliverable gate — the brief requires a live demo)
A clean clone plus npm ci plus typecheck plus test passes with no credentials configured (clean-clone gate)

A milestone is DONE only when every applicable box above is checked by the verifier, and never by the building agent marking its own work. This genesis repo has no engine code yet — every gate above becomes checkable starting with M1's own PR and its own verifier.
